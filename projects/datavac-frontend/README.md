# DataVac — Frontend

> Командный проект: веб-приложение для работы с информацией о вакцинах. Этот каталог содержит портфолио-описание моего вклада в frontend-часть проекта. Исходный командный репозиторий: https://github.com/DataVac-masterskaya/data-vac-frontend

## О проекте

**DataVac** — информационный веб-сервис с каталогом вакцин и справочной информацией: вакцины, инфекции, ингредиенты, противопоказания и инструкции. Frontend был реализован как Next.js-приложение с адаптивным интерфейсом и интеграцией с backend API.

Моя задача в команде заключалась в разработке и интеграции frontend-функциональности: от UI-компонентов и адаптивных страниц до работы с API, поиска, фильтрации, детальных карточек вакцин, платежного сценария и генерации PDF.

## Моя зона ответственности

- Разработка React/Next.js страниц и переиспользуемых UI-компонентов.
- Реализация адаптивных интерфейсов для desktop, tablet и mobile.
- Интеграция frontend с REST API и переход от mock-данных к реальным данным backend.
- Разработка mapper-логики и TypeScript-типов для согласования API-контрактов с UI.
- Реализация каталогов вакцин, ингредиентов, инфекций и противопоказаний.
- Реализация поиска, фильтрации и сортировки, включая работу с URL/search params.
- Разработка страницы детальной информации о вакцине с вкладками и информационными секциями.
- Реализация платежного сценария и интеграции CloudPayments.
- Генерация PDF-инструкций по данным страницы вакцины, включая QR-коды и кириллические шрифты.
- Исправление UI/UX-дефектов, responsive-поведения, scroll-навигации и обработки API-ошибок.
- Участие в E2E-тестировании критических пользовательских сценариев.

## Ключевые реализованные задачи

### 1. Каталог вакцин

- Реализовала подключение списка вакцин к `GET /api/v1/vaccines/` вместо статических mock-данных.
- Настроила отображение параметров поиска, сортировки и фильтрации.
- Реализовала mapping frontend-параметров в формат API.
- Настроила адаптивную таблицу с разными представлениями для desktop/tablet/mobile.
- Добавила sticky header и scroll-to-top поведение.

### 2. Страница детальной информации о вакцине

- Реализовала интеграцию страницы с API.
- Обновила модели данных и mapper-функции под backend-контракт.
- Реализовала вкладки с обработанной информацией и инструкцией.
- Разработала информационные секции, sidebar и связанные UI-компоненты.
- Добавила отображение способов введения, противопоказаний, возрастных ограничений и других характеристик.

### 3. Ингредиенты, инфекции и противопоказания

- Перевела страницы со статических данных на реальные API-запросы.
- Реализовала поиск, сортировку и фильтрацию.
- Настроила обработку отсутствующих данных и API-ошибок.
- Для противопоказаний реализовала построение фильтров из ответа API и группировку данных.
- Для инфекций реализовала mapping категорий и параметров сортировки.

### 4. Поиск

- Разработала страницу результатов поиска.
- Реализовала состояния загрузки, пустого результата и ошибки.
- Добавила фильтрацию и сортировку.
- Подключила API поисковых подсказок.
- Использовала URL-параметры для сохранения состояния поиска и фильтров.

### 5. Платежный сценарий

- Разработала интерфейс пожертвований.
- Реализовала выбор суммы и регулярного платежа.

- Добавила валидацию email, состояния успешной/неуспешной оплаты и обработку ошибок.

### 6. PDF-инструкции

- Реализовала генерацию PDF-инструкции на frontend по данным страницы вакцины.
- Добавила QR-коды для ссылок на инструкции.
- Настроила шрифты и поддержку кириллицы.
- Привела структуру и визуальное оформление PDF к Figma-макету.

### 7. UI, responsive и UX

- Реализовала и дорабатывала sidebar, header, navigation и footer.
- Создавала переиспользуемые карточки, панели, строки таблиц, фильтры, popup/drawer-компоненты и другие элементы UI.
- Исправляла responsive-поведение на разных breakpoint'ах.
- Исправляла проблемы со scroll, sticky header, декоративными слоями и доступностью интерактивных элементов.
- Выполняла pixel-perfect доработки по Figma.

## Что было важно с инженерной точки зрения

Проект позволил работать не только с визуальной частью frontend, но и с полным циклом интеграции данных: API-контракт → TypeScript-типы → mapping → server-side fetching → UI → обработка ошибок → responsive-представление.

Особое внимание уделялось тому, чтобы интерфейс не зависел от mock-данных после подключения backend: страницы переводились на реальные API, параметры UI сопоставлялись с параметрами сервера, а ошибки API обрабатывались явно.

## Запуск проекта

### Системные требования

- Node.js — версия, совместимая с используемой версией Next.js 16.
- npm / yarn / pnpm / bun.
- Доступ к backend API DataVac для полноценной работы страниц, использующих серверные данные.

### Установка

```bash
npm install
```

### Переменные окружения

Для локальной разработки необходимо указать URL backend API:

```env
NEXT_PUBLIC_API_URL=https://datavac.rassokha.pro/api/v1
```

Фактические значения секретов и ключей платежной системы в публичное портфолио не добавляются.

### Development

```bash
npm run dev
```

После запуска приложение доступно на `http://localhost:3000`.

### Production build

```bash
npm run build
npm run start
```
